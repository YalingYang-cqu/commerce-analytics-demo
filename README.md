# 跨境电商成本利润经营分析 Demo

面向数据 / B 端 / 电商产品岗位的**可交互作品集**。用 Vue3 高保真前端还原实习期间从 0 到 1 搭建的跨境电商成本利润分析体系：采购与头程成本、销量广告、订单利润、库存成本流转。

页面数据全部为**虚构 Mock**，不连接任何公司、生产或内网服务，也不包含真实店铺、商品或经营数据。

| 角色 | 周期 | 方向 |
| --- | --- | --- |
| 产品经理（需求调研 / 业务规则 / 原型与 PRD / 数仓口径 / 验收） | 2026.04 – 2026.08 | 跨境电商 ERP · 成本与利润分析 |

## 本地运行

环境要求：Node.js `>= 20.19`，包管理器 [pnpm](https://pnpm.io/) `>= 8.8`。

```bash
pnpm install
cp .env.example .env.development   # 若本地还没有环境文件
pnpm dev
```

浏览器打开 [http://127.0.0.1:7083/charts/](http://127.0.0.1:7083/charts/)。默认进入「采购批次成本」，左侧菜单可切换全部演示页。

构建静态演示：

```bash
pnpm build
pnpm serve
```

开发和构建都强制走本地 Mock（`VITE_USE_MOCK=true`）。请勿在本仓库中填写真实服务地址、密钥、账号或经营数据。

可选：将成本中心打成可双击打开的单文件 HTML：

```bash
pnpm build:single
```

产物路径由 `scripts/inline-single.mjs` 指定，默认写到仓库外的离线 HTML，便于投递时单独附带。

## 为什么做这套产品

跨境电商算利润，难点不在「做一个报表」，而在四件事同时成立：

1. **成本算得清**：同一 SKU 多供应商、多批次，采购价和头程费要落到单件。
2. **销量广告看得全**：SC / VC 双渠道、广告 30 天归因，不能多系统来回切。
3. **利润拆得开**：亚马逊 80+ 费用项要归到订单 × MSKU，还能下钻到亏损对象。
4. **账对得上**：平台报告只有数量没有成本，销货成本和期末货值必须可追溯、可对平。

四期项目按业务依赖递进，最后收成一条数据价值链：

```
采购单价 + 头程分摊
        ↓  FIFO 绑定到入库批次
SKU 综合成本 / 批次结存
        ↓  出库拆行生成成本流水
订单 / ASIN / MSKU 级销货成本
        ↓  叠加上销量、广告、平台费用
SC 订单利润（收入 − 支出 − 库存成本 + 其他收入）
```

- 一期回答「成本是多少」
- 二期回答「卖了多少、广告花了多少」
- 三期回答「到底赚不赚钱」
- 四期回答「成本怎么流转、怎么对账」

## 分模块总结

### 1. 采购物流成本（成本一期）

**一句话**：以 SKU 为核心，打通「采购 → 头程 → 综合成本」，让运营、采购、物流、财务用同一套口径看在售货的真实成本。

**要解决的问题**

- 同一 SKU 多供应商、多批次，采购单价波动大，当前在售成本说不清。
- 头程运费 / 关税 / 杂费按运单整笔记，摊不到 SKU 单件。
- 综合成本靠 Excel 月底估算，时效差、易错，四方各算各的。

**产品方案**

- 落地三张报表：采购批次成本、头程物流批次成本、SKU 综合成本。
- 数仓按 ODS → DWD → DWS → ADS 四层建模，页面吃应用层宽表。
- **FIFO 分仓核算**：采购单价与头程分摊在入库批次绑定为单位综合成本；按 `(SKU × 店铺仓库)` 独立排队，出库以亚马逊订单触发扣减。店铺仓库是虚拟维度，用来隔离不同店铺 / 站点的货，不依赖物理仓库存对账。
- 头程支持按数量 / 计费重量 / 体积（CBM）三种分摊基准；在途用预估，结算后回填并重算受影响批次。
- SKU 综合成本内置四类预警：周转过慢、超卖、批次成本涨幅、库存超期。
- 批次明细可追溯 PO 单号 → 运单号。

---

### 2. 销量与广告统计（成本二期）

**一句话**：把 SC / VC 销量、广告、流量、退货收成一套数据底座，运营不用再跨系统看数。

**要解决的问题**

- SC 销量、VC 销量、广告分散在多个旧页面。
- 维度写死在 ASIN，切不了父 ASIN / SPU / 品牌 / 负责人。
- 只有日汇总，没有小时级分时，广告调优缺少依据。
- 广告存在 30 天归因回补，和销售日口径对不齐。

**产品方案**

- 统一链路：源表 → DWD（原子粒度，支持 30 天广告归因回补）→ DWS → 前端。
- 销量统计支持综合 / SC / VC 三视图：综合看分摊占比，SC 看店铺与同比，VC 适配无店铺维度。
- 销售明细按父 ASIN、ASIN、SPU、SKU、分类、品牌、负责人、站点、渠道动态聚合。
- 趋势图提供**归一化 / 原值**双模式。归一化把销量件数、广告花费、ACOS 映射到 0~100%，解决不同量级指标无法同轴对比的问题。
- ASIN 看板（产品方案，代码在 `src/views/sale-analysis/asin/`）提供日销售、小时级分时汇总、多日期分时对比。

---

### 3. SC 订单利润

**一句话**：把 80+ 亚马逊费用项归到订单 × MSKU，让运营从「卖了很多」走到「知道赚不赚钱、亏在哪、广告还能加多少」。

**核算公式**

```
订单利润 = 平台收入 − 平台支出 − 库存成本 + 平台其他收入
```

库存成本来自一期 / 四期；平台收入、销量、广告来自二期。本模块是前几期数据的汇总与经营呈现。

**要解决的问题**

- 佣金、FBA 配送、促销、退货、广告、仓储等散落在不同报告，归不到订单。
- 大量费用行不带 SKU，分摊规则不统一。
- 只能看店铺汇总，定位不了亏损 ASIN / 订单。
- 不知道广告加到多少会亏。

**产品方案**

- **16 项费用两段式分摊（P0–P5）**：先为费用行找 MSKU，再按结算日摊到当日订单明细。金额型按销售额占比，按件收取按销量占比。
- 核心原则：**费用按结算日重分，不追溯改写历史利润**。即使费用行带真实订单号，也只用来取 MSKU，保证入账时点与利润归属时点一致。
- 六维 Tab：看板 / 父 ASIN / ASIN / MSKU / SPU / 订单，支持层级下钻。
- 利润拆解抽屉：收支公式 + 15 项费用瀑布图，费用格可再下钻子项。
- ASIN Tab 内置盈亏平衡测算：调单均广告和订单量，预估利润增量。
- 看板三张经营诊断卡：利润效率、广告压力、亏损对象复盘。
- 服务端数据权限：运营只看自己负责的 ASIN，管理层看全量。

### 4. 库存成本流转（成本中心，独立负责）

**一句话**：亚马逊报告只有数量、没有我们的采购和头程成本。把销货成本和期末货值从「月底人估」做成可追溯、可对平、可过账的系统能力。

**要解决的问题**

- 平台只告诉你动了多少货，不告诉你这批货值多少钱。
- 库存流水和成本流水两套账，数量对得上、金额对不上，越查越慢。
- 补录单价如果改原始事实，重算不再幂等。

**产品方案：三中心，而不是一张大宽表**

| 中心 | 性质 | 记什么 | 对应页面 |
| --- | --- | --- | --- |
| 平台出入库流水 | 事实层，只追加 | 动了多少货，跟亚马逊报告对得上 | 库存成本流水（主表 + 一级展开） |
| 批次结存 | 状态层，反复更新 | 这批货还剩多少、值多少 | 批次结存 |
| 成本流水 | 核算层，只追加 | 这次从哪几个批次动掉了多少钱 | 库存成本流水（二级展开） |

一条销售如果按 FIFO 吃掉两个批次：平台流水仍是 1 行，成本流水落 2 行，两行数量必须加回平台数量。补录单价只红冲重出成本层，不改事实底稿。

**三层对平门禁**：事件分摊、单批次、仓库汇总，**任一层不平当日不过账**。财务可信度做成产品能力，而不是先出报表再人工修。

复杂场景收进同一套批次模型：有源签收、FIFO 拆行、退货建 RB、调整净额、跨仓成本平移、补录红冲、良品 / 次品隔离、无源暂估。同属性不足才建暂估，不允许良品扣次品。

**实时性 vs 准确性**：分钟级同步事实流水，成本计价异步，日终对平后才过账。页面同时展示同步时间、计算状态、对平状态，避免把「刚同步的数量」当成「已过账的财务数」。

本期范围卡在 SC-FBA 的算清和看清，明确不做预警补货和利润页改造，但把订单 / ASIN / MSKU 级成本字段留给利润归因。
